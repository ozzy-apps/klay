# Klay handoff

## Project
Klay is a native desktop sculpting prototype. The UI is a ZBrush-style workspace (menu-bar palettes, four dockable trays, fixed shelves), ported from the interactive HTML reference `ui-mockup.html`. The Material 3 version described in steps 1–4 below was replaced in step 5. UI copy should only be functional.

## Current implementation — 0.6.0 (see Step 44; the summary below describes 0.4.0)
- Native ZBrush-style Klay UI, preserving the readability touch-up. Current release has 33 tools, including six masking brushes, Clip Line, FormSoft/FormHard and Zipper/Stitch/Rake relief. Compact Sculpt/Mask working sets, original previews and a searchable/category-filtered B catalog keep them discoverable.
- Space palette: left HSV picker; Draw Size → Z Intensity → Focal Shift → RGB Intensity → brushes. All values affect the real stroke.
- Application version: `Cargo.toml` / `Cargo.lock` **0.4.0**. Project format **4**, backward readers for 1–3. Brush library format **v1**; workspace layout remains **v2**.
- New engine modules: `brush_asset.rs`, `paint.rs`; new UI modules: `brush_preview.rs`, `asset_library.rs`, `brush_ui.rs` (workspace child). Existing multires/project/renderer code retains per-level color and undo data; Wedge transfers paint.
- Linux icon/launcher installer: `scripts/install-desktop.py`; local versioned AppDir: `scripts/package-linux.sh`. No publish or git operations are implied. Release complete; implementation and final verification are recorded in steps 39–42 below.
- Historical steps below explain earlier prototype states. Their old disabled-control lists and initial mockup constraints are superseded by the current release and latest user requests.

- Brush/material previews: `sphere_image` renders a shaded sphere with the brush's stroke (CPU, 96 px, cached per kind/material/subtract as egui textures).
- Widgets: `zslider` (ZBrush bar slider; `line` variant for the shelf), `seg`, `big_button`, `thumb`, `brush_tile`, `color_picker` (mesh gradients), `menu_item`, `kv`, `tag`.
- 8 tests pass (`cargo test --release --offline`): layout moves/reorder/undock, roundtrip, damaged files, title click collapses, dock-button drag to all four edges, pen-drag tray scrolling, window sizes/focus, preview images.

- Known gaps: Persp toggle, Sym, paint modes, Zcut, Focal Shift, stroke/alpha/texture/masking/transform are placeholders; History shows availability only (the engine has no stroke list); the colour picker has nothing to paint with yet.

## Step 47: 0.6.3 — crossing Clip Line cuts stick out (2026-10-23, Claude Code)

## Step 71: GPU chunk culling — phase 1 of "points for sub-pixel triangles" (2026-10-25, Claude Code)
- User asked for faster drawing of very dense meshes (points for sub-pixel triangles) and approved a three-phase plan: (1) GPU chunk culling, (2) compute point splats for chunks whose triangles are under about a pixel, (3) fewer splats when far away. Measured first with a throwaway build at 61M vertices / 123M triangles: one `draw_indexed` of the whole level cost 13–17 ms whatever the screen size (triangle setup bound, shading ~2 ms), hardware point lists were no faster, and a compute splat of every vertex (64-bit `atomicMax` of depth << 32 | vertex id) cost ~2.5–3 ms but 6 ms when the model is small (atomic contention) — that is phase 3's reason.
- Phase 1 (this step): `bounds.wgsl` refits each chunk's box and normal cone (meshoptimizer-style cutoff) on the GPU after the normal pass, for chunks that moved or were re-shaded plus their edge neighbours (`upload_dirty` builds `bounds_work`; `bounds_all` after a Transpose release's affine pass, `rewrite_from`, or when over half are listed). `cull.wgsl` writes one `DrawIndexedIndirectArgs` per chunk (instance count 0 when culled: frustum narrowed to the document frame, cone back-face test with a perspective or orthographic camera) and the active subtool is drawn with one `multi_draw_indexed_indirect`. Draws stay in chunk order: a packed, counted variant was measured no faster and let depth ties at silhouettes resolve differently each frame.
- `MeshBuffers` gained bounds, per-chunk draw ranges (`full_ranges`, or `visible_ranges` into the visible-triangle buffer, written in `sync_marks`), draws, counts. The active subtool uses a new `vs_active` entry (parked stand-ins keep `vs_main`): its instance index is the draw's first triangle (`first_instance`, needs `INDIRECT_FIRST_INSTANCE`), added to the primitive index in `groups.wgsl` (`VsOut::prim_base`). WGSL gotcha: `active` is a reserved word.
- Culling pauses during a Transpose preview, drops the cone test under Live Boolean, and is off for PolyF on GPUs without first-instance draws. `--render triangles` turns it off; `--camera-distance K` scales the framed camera; `--frames` logs what culling drew; `--selftest-cull` compares culled and whole frames pixel for pixel after eight steps (views, a GPU Grab during and after, Offset X, half hidden, PolyF).
- Next: phase 2 (splat pass + resolve into the depth buffer, per-chunk choice by vertices per pixel from the cull pass), then phase 3.
